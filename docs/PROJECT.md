# 月石 Feldspar：面向家庭鼾声困扰的开源睡眠辅助软硬件方案

申报建议：第四届开放原子大赛·2026 开源行业解决方案创新赛，开源智能硬件解决方案赛道。

## 项目摘要

月石面向受鼾声困扰的家庭及同睡伴侣，以 ESP32-S3 床头主机、枕下提醒垫和微信小程序探索睡眠辅助体验。当前提交以可复现的设备控制、结构化声学观察、停止保护和真实状态表达为核心：设备计算版本化声学特征，后端校验质量与连续性，小程序以请求令牌和驱动回读区分操作意图与执行结果。项目开放固件、小程序、后端和测试，便于开发者复现与改进。

当前版本属于工程开发候选，自动干预关闭，未接入经验证的鼾声分类模型；没有提供真实家庭使用效果、临床验证或医疗诊断能力。项目希望先建立可检查的工程基础，再完成样机联调、数据评估及安全标定。

## 应用场景与需求

家庭卧室中的辅助设备需要同时处理环境噪声、同睡者体验、设备控制和个人反馈。项目提出的需求是假设：用户需要明确知道设备是否连接、设置是否执行，以及哪些记录可信。尚未完成系统用户访谈与真实家庭试验，不能把这些需求假设写成已验证市场结论。

产品形态包括床头主机、枕下有线提醒垫及小程序。现阶段可用软件复现的是协议、状态管理与观察链路；实物控制效果另行提交演示证据。

## 技术架构

1. 设备侧：ESP32-S3，麦克风采集、DSP、灯光/音频/振动接口、实体按键与停止锁定。
2. 协议侧：BLE 请求令牌与驱动回读；可选 `feldspar-features-v1` 结构化 MQTT 链路，要求独立设备凭据。
3. 服务侧：FastAPI、Pydantic、SQLite/MySQL 适配；特征校验、最新窗口状态及命令/回执记录。
4. 交互侧：微信小程序；区分设备回读、云端待同步、未知值和数据不足。导出候选默认 mock 展示。

只观察通路：1 秒 PCM 在设备内用于计算 → 特征与质量标记 → 后端连续性检查 → 工程观察结果。当前只观察结果不生成晨报事件，也不触发自动干预。后端历史音频接口和参考决策器保留但默认关闭，不将它们描述为已通过实机验证的当前产品闭环。

## 可主张的工程贡献

**贡献一：可核查的结构化声学观察链路。** C 特征实现与独立 NumPy 参考进行数值对照，协议包含版本、时钟、序列、会话与质量位。热身、削波、采集缺口、自噪和静音影响观察有效性；不把规则分值写成分类准确率或概率。

**贡献二：以回读完成控制确认。** 小程序用请求令牌匹配通知，拒绝迟到回执；云端接收或排队不等于设备执行。设备确认后云保存失败时保留本地回读并提示待同步。停止需明确锁定与输出关闭回读。

**贡献三：未知值与自动动作的明确边界。** 缺失观测保持 null，不用零值或默认“平稳”替代。当前固件自动执行关闭，停止、预算、限时等逻辑有主机检查，物理参数仍需测量。

这些是本项目有证据支持的设计与工程实现，不构成相对所有同类产品的首创性或领先性证明。FFT、RMS、自相关、BLE、MQTT 本身都是已有技术。独立对照实验完成前不宣称识别更准、功耗更低或止鼾更有效。

## 当前验证与局限

以本候选 `docs/VALIDATION.md` 的最新结果为准。主机测试使用合成信号、模拟 wx、替身外设、内存 MQTT 和临时 SQLite；它们验证协议与逻辑，不验证卧室声学、蓝牙射频、物理输出、正式身份系统或临床效果。

没有可申报的真实鼾声分类准确率、止鼾成功率、降低分贝、续航或用户增长数据。历史参考训练包中的估计值和旧展示数值不作为本候选证据。没有附带或开放真人录音、睡眠记录、训练集与模型权重。

## 开源与长期维护

自研代码采用 Apache-2.0，保留 cJSON MIT 许可与其他依赖声明。开放范围包括可运行源码、协议和主机检查；不包含完整量产制造资料。维护者按贡献指南接收 Issue/PR；当前公共仓库尚未发布，不虚构社区规模、Star 数量或外部贡献。

里程碑采用退出条件而非未经确认的时间承诺：公开可复现基线 → 独立测试服务与样机联调 → 授权真实数据的独立评估 → 执行器标定及长稳/OTA 验收。上述证据齐备后才讨论开放自动提醒。
