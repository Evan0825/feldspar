# 月石小程序 UI 设计规范 · v1.0

方案 5「参考图风格」为后续原生微信小程序的视觉基线。适用范围包括四个底栏页面、二级页面、抽屉、弹窗和各类数据状态。

## 视觉依据

以 [睡眠首页](design/moonstone-ui-v1-sleep-home.png) 和 [单晚数据详情](design/moonstone-ui-v1-sleep-detail.png) 为定稿基准。两张图使用同一晚的示例数据。其他页面按相同的颜色、字号和控件规则设计，按各自任务组织内容。[旧版四屏](design/moonstone-ui-approved-20261028.png) 和 [逐页选稿记录](design/review-decisions-20261029.md) 用于回查已有页面的功能和交互约定。

## 字体与布局

以下为以 390 px 宽度设计时的逻辑尺寸。WXSS 按 `750 / 390` 换算为 rpx。

| 层级 | 字号或尺寸 | 用法 |
| --- | --- | --- |
| 页面标题 | 导航标题 18–20 px，大标题 28–30 px | 系统无衬线，字重 600–700。每页只出现一次页面标题 |
| 主指标 | 56–65 px，字重 700 | 单位 16–19 px，数字与单位留间距。数据页优先用等宽数字 |
| 模块与正文 | 模块标题 16–18 px，正文 14–16 px | 说明、状态和标签用 12–14 px。图表轴标签空间受限时可用 10–12 px |
| 边距与间距 | 页面两侧 16–20 px，模块间 16–24 px | 模块内部优先用 8、12、16 px 间距 |
| 卡片与列表 | 卡片圆角 20–26 px，进度条目圆角 14–16 px | 列表行高通常 52–60 px。纸白底、轻边框或细分隔 |
| 控件 | 主按钮高 48 px，胶囊圆角 | 交互热区至少 44×44 px。底部固定操作避开系统安全区 |

正文、控件和大标题统一用系统无衬线。卡片采用平面色块，优先用留白区分模块。长文案、大字号和窄屏允许换行，数值与单位、底栏标签和关键操作保持可辨识。

## 组件与页面用法

- **导航与图标** · 保留原生底栏「月石／睡眠／AI／我的」及现有四枚实心图标。未选图标用暖灰，选中图标用月亮黄实心填充，选中文字用深色。列表和控制图标复用项目现有素材，按同一角色保持大小与线宽一致。
- **按钮与选择** · 一组任务突出一个主操作。确认、保存、查看数据用月亮黄胶囊和深字；次操作用纸白、细边框或文字入口。筛选和选项默认纸白，选中用浅月黄和深字，保留选中语义。高风险操作用独立确认与危险色。
- **日期** · 睡眠首页使用一排圆形日期快速回看，显示月份和当前选中日。日期变化时，主卡、晨间反馈和「查看数据」使用同一晚。「睡眠数据」只设一个日期选择入口，显示日／周／月，沿用原有日历和范围交互。
- **数据卡片** · 睡眠首页先显示有效监测时长，再显示提醒次数与后续响应；有数据依据时可加一句总结。数据质量放详情，首页保留「查看数据」「晨间反馈」。单晚详情先呈现日期、采集进度、时长与质量，再呈现数据图和事件。
- **图表** · 同单位的提醒与响应共用零基线和刻度，胶囊内标次数，柱下标名称。整晚事件用时间轴，「全部记录」放在图旁。保留部分同步提示及已选提醒的触发与响应。周、月趋势沿用各自的口径和图形，缺失留空。
- **数据图标** · 监测时长用月亮，鼾声用声波，提醒用振动，响应记录用对勾，采集进度用日历。图标搭配短标签和数值，浅色底区分指标。进度条只在有明确目标和有效进度时显示；单晚数值使用数字或同尺度比较，有时序记录时才绘制趋势。
- **进度与异常** · 「数据采集」直接显示已采集晚数，例如「已采集 6/7 晚」。首轮采集与持续校准使用当前实际阶段，状态待回读时显示待确认。加载、空态、离线、权限失败、设备失败与部分同步都有可辨识的提示和对应操作。
- **列表、表单与抽屉** · 设置项用「名称／当前值／方向图标」，开关只用于可独立启停的能力。表单标签常驻，错误靠近对应字段，提交与加载中防止重复触发。抽屉标题说明当前操作，保留一个确认入口和一个退出方式。
- **设备与文案** · 真实设备图片保留主机、提醒垫和连接线。一个模块只用一个功能标题。只保留有助于决策或操作的数据、字段、状态、错误和后果；可选说明收进上下文帮助。

## 现有页面的交互约定

- 首页顶部导航只出现一次「月石」，不在正文重复品牌。普通菜单使用一致的图标、字号和背景；「个性化偏好」不高亮。
- 声音和夜灯只显示功能名，颜色和克制动效表达运行状态，不加「已关闭／已开启」文字；同时保留读屏标签。夜灯使用贴近月石圆顶设备造型的图标。
- 声音播放控制保留音量、定时关闭及当前定时选项。设备详情的「版本与同步」固定包含固件版本、本地模型和上次同步，按真实状态展示。

### 首页

紧凑方案卡：小号「当前温和方案」；「初始方案」与「收集阶段」标签同行；真实进度；细连续进度条；整行「查看方案」。不在首页堆叠具体参数。

声音与夜灯并排；「问 AI」和「实时状态」上下排列，一项一整行。底栏保持「月石／睡眠／AI／我的」。

### 温和方案详情

默认只展示当前阶段、真实进度与当前运行方式；完整阶段收进「全部阶段」，展开后使用紧凑纵向时间线：初始方案→初步方案→校准期方案→持续迭代。阶段介绍不占据默认首屏。

下方列当前运行方式、固定默认振动及声音／灯光排除项。保留一次必要的阶段转换说明。未知阶段或进度显示待同步；没有真实策略记录时不因累计七日直接宣称初步方案、校准或持续迭代已生效。

### 我的

设备卡下方的第一项为「个性化偏好」，与其他菜单同样式，不特别着色；继续保留设备、授权、更新、分享、隐私入口。

AI 与数据授权展开后，以一行开关控制资料读取，保留一次使用范围说明；「AI 记忆」「对话记录」用细分隔线的普通列表入口，不使用强调色大按钮，不重复“管理”或开关状态文案。

### 个性化偏好

- 称呼与同睡情况复用首次使用的字段，可修改并重新打开核对。
- 振动是固定默认提醒方式，以只读行显示，不提供勾选、开关或取消。
- 分组统一为「提醒方案」：振动为固定默认项；「声音提醒」「灯光提醒」对新用户默认勾选，取消勾选即不纳入方案。已有保存的排除选择按原含义回显，不能被方案或 AI 覆盖。
- 方案选择不影响用户手动播放助眠声音或控制夜灯。该规则放在上下文帮助中，不重复铺文案。
- 保存需等待服务确认；失败保留编辑内容，不能显示虚假成功或修改设备配置。

## 验证与边界

设计评审使用独立清晰页面。文字和控件直接渲染，每页至少按 390×844 逻辑视口的 3 倍输出。所有大配图复用同一高清源图和 320×190 逻辑尺寸，夜灯仅增加暖光，保持设备造型、视角和主体尺寸。

2026-10-29追加执行：用户授权剩余6页直接采用推荐方案，无需再次选稿。隐私采用一次明确确认，AI资料读取单独授权；睡眠首屏保留时长与主要入口，指标和时间分布进入同一夜晚的二级详情；晨间反馈三个短问题同屏，反馈入口不先展示趋势图；AI保留来源、最多两个推荐问题，依据折叠，建议独立确认并等待回读，历史续聊不替换原来源。

2026-10-29追加确认：统一原生睡眠数据的日历交互。保留一个「查看数据」入口；普通进入默认今天早晨结束的记录，明确昨晚至今晨的起止日期。来自 AI 等明确历史来源的入口保留原日期。数据详情只留一个日期入口，日／周／月、年月及日期、今天／本周／本月都集中在同一个日历抽屉；草稿点「查看数据」才生效，取消保持当前范围。周一至周日、自然月；未来日期禁选且不计入覆盖率。

日页聚焦整晚事件时间轴与触发／提醒／响应，默认显示选中提醒，「全部记录」展开整晚时间事件。只关联服务明确给出的触发与响应，不能用时间相邻推定关系。周采用方案2：当前与上周同期双线对比，辅以提醒均值和已填写感受；月采用方案3：按月内周段汇总。月→周→单晚下钻后返回保留原范围、点选和滚动位置；月初/月末不扩展到月外。

周期主图聚焦每有效监测小时的鼾声事件；缺有效时长或事件数时不计算频率，覆盖率与可计算频率的样本数分开显示，缺失不按0。提醒均值只按有该指标的有效夜晚计算，晨间感受保留独立样本数。没有已确认方案变更记录，不放置虚构节点。设备无依据的深浅睡、心率等不展示。快速切换不能被旧日期的报告、事件或周期请求覆盖。

检查实际页面、交互和导航；设计图不能替代功能或硬件验收。设置待确认、设备离线、数据不足和失败时使用真实状态。界面状态与动效不能替代错误提示、读屏语义或硬件回执。

## 命名与全页面文案（追加确认）

助手统一叫「AI」，不使用产品名前缀。底栏第一项为「月石」；「今晚设置／今晚提醒」等时段含义保留。所有已声明页面逐页检查：原生导航已说明页面名时不再叠加正文品牌或相同标题；加载只保留一条状态；滑块不再附带操作常识；隐私、非医疗边界、设置后果和数据来源在相关授权或判断处保留一次。失败已在页面展示时不再重复弹同一条 Toast。

2026-10-30文案精简：日历不展开操作教程、未来日期规则或重复“已选”提示；保留一个选中范围及本周/本月快捷操作。月模式不重复打印上方年月。仅底部保留取消，移除重复关闭文字；统计规则保留在数据说明中。预览外部不铺设计阶段和操作说明；示例来源标记保留，详细演示边界折叠。

2026-11-02用户授权先更新试版：按日／周／月的统一数据交互落地。日页以有效监测时长为主数字，三项为鼾声频率/提醒次数/后续响应；周期页以平均鼾声频率为主数字，保留点选浮层、独立反馈样本及回看入口。统一日历和简洁文案延续；AI入口保留实际夜晚日期，不自动发送问题，不补造解读。

## 全量升级顺序

开始时，以微信开发者工具实际导入的原生项目和其中的 `app.json` 确认目标版本、注册页面和分包。以下短名对应 `pages/<短名>/index`，覆盖本次核对的 22 个路由。晨间反馈、偏好、隐私和设备更新等页内流程也随所属页面验收。

| 批次 | 页面 | 验收重点 |
| --- | --- | --- |
| 1 · 共享样式与基准 | `report`、`report-detail` | 先在 `app.wxss` 归并颜色和组件样式，再同步原生导航、底栏配置与图标素材。用两张定稿图验收同一晚首页与详情 |
| 2 · 一级导航 | `home`、`ai`、`profile` | 同一套底栏状态与列表组件；月石当前方案、AI 来源与我的入口均可找到 |
| 3 · 数据与事件 | `trends`、`events` | 日／周／月、历史回看、范围切换、图表口径、事件和晨间反馈保持连贯 |
| 4 · 登录与设备 | `onboarding`、`setup`、`calibration`、`readiness`、`device`、`live` | 登录、隐私、绑定配网、设备回执和版本同步覆盖正常、等待、失败与重试 |
| 5 · 方案与控制 | `strategy`、`tonight`、`sound`、`light` | 真实阶段和采集晚数、手动推送、固定振动偏好、声音定时关闭及夜灯控制 |
| 6 · AI 二级流程 | `ai-detail`、`ai-chat`、`ai-plan`、`ai-records`、`ai-memory` | 原夜晚来源、授权、历史、应用方案确认与设备回读 |

每批在微信开发者工具验收实际页面和交互。至少核对默认、选中、禁用、加载、空态、失败和权限或设备受限场景中适用的状态，以及返回、重试和安全区。在常用窄屏和放大字体下检查截断、溢出、热区与对比度。交付逐路由实屏和功能核对结果，标明示例数据与实机验证范围。
