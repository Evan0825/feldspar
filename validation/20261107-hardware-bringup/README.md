现装固件启动日志显示联网 OTA 自动轮询。配网验收需要禁止访问公网的 2.4 GHz 测试网，验证配网后获 IP、断网状态和重连。本地历史 `1.0.2` 镜像的 ELF 指纹与样机不同，保留现装版本的启动证据，历史镜像不作回滚依据。

咖啡店联网检查中，Mac 的 Wi-Fi 可访问公网。现装版通过 `0x51` 回报 `1.0.2`；历史源码的中止命令只清理一次传输，未找到关闭自动轮询的配网接口。咖啡店网络未写入样机，后续改用手机隔离热点完成配网。Mac 配网期间保持原联网方式，BLE 负责下发和回读。

候选源码已将扫描请求交给 Wi-Fi 事件循环处理。如果驱动正在连接，先等待该次连接完成，失败时让扫描在下次自动重连之前运行。扫描结束或失败后恢复重连。主机测试先复现原版失败，再通过重连冲突、成功关联后扫描、扫描失败后的恢复、重复请求和清除网络后不重连等场景。

只读手机预览页复用仓库的 BLE 桥接。用实测完整广播名筛选样机，订阅 `FF03`、`FF04`，仅发 `0x42` 读 Wi-Fi 状态及 `0x34` 读音效列表。开发者工具生成预览二维码，模拟微信接口检查通过，手机回报已核对。测试 AppID 和二维码保存在联调副本。

手机配网预览复用同一桥接。修正默认 ATT MTU 为 23 字节，使 18 字节的旧版配网帧可用。若手机不支持设置 MTU，仍查询系统可提供的单包上限。模拟微信检查验证 `0x41` 单次下发，`0x42` 复核目标网络和 IP，网络不一致时不给成功状态。开发者工具已生成预览，手机直接下发结果待回报。

首次手机配网页显示 `PROVISION_TIMEOUT`，在「蓝牙已连接」之前退出。未得到小程序已经下发 `0x41` 的证据。之后 Mac 回读到 `隔离热点` 仍保存且未连接，当时也未扫到该热点。台架人员观察到灯带亮起。配网页仅调用蓝牙连接、`0x41` 配网和 `0x42` 查询，未发现灯光写入路径。此前样机因验证配置保存而重启，旧固件会恢复灯带记忆状态，实际亮灯原因待对照。新版预览分开提供只读检查和配网，模拟微信确认只读按钮只发 `0x42`，并能报告超时的具体蓝牙接口。手机对照测试待回报。

新版预览的手机只读检查通过。手机发现同一台 `HAOMIAN-SLEEP_〈样机后缀〉`，连接并订阅协议 `1.0`，读取到 Wi-Fi 配置已保存、当前未连接。下一步在隔离热点广播可见时复测手机下发。

候选已有环形缓冲满时重试的逻辑。另用模拟音频驱动复现了自然结束仍会清空尾部 PCM 的问题。修正后，文件读完会等环形缓冲与 I²S DMA 尾部，超时回报 `SFXERR,drain`。显式停止仍取消等待并停止，主机回归覆盖自然结束、尾部等待时停止和超时。候选音效的实际时长、末尾和中途停止仍需在台架核对。

候选的 ESP32-S3 默认和只观察配置已通过编译。其 8 MB Flash 配置匹配现装镜像头与现有分区布局。本次沿用项目不烧录约定，板上固件保持 `1.0.2`。自动提醒、实际输出停止、云端 MQTT 及首夜闭环仍待匹配候选和对应测试环境。

安卓手机随后回报扫描阶段的 `PROVISION_TIMEOUT · getSetting`。电脑端复现微信权限读取不回调时扫描提前退出；修正为仅在该接口超时时继续尝试原生 BLE 扫描，由系统继续执行权限检查。明确拒绝位置权限或原生扫描返回拒绝时仍停止。新增回归通过，安卓修正版预览已生成，手机配网仍待回报。

外置 Flash 持久化测试的受控重启中，现装 `1.0.2` 串口回报灯带初始化为 `OFF`。本次启动未复现灯带亮起，先前手机报超时时的灯带状态变化原因仍未确认。

重新生成安卓修正版预览后，手机已发现并连接样机，协议 `1.0`，随后显示 `下发 Wi-Fi 配置 · WIFI_CONNECT_FAILED`。扫码时为了让手机联网，测试热点曾关闭。错误后的 Mac 扫描未发现该热点，BLE 回读配置仍保存但未连接。需要在页面加载后保持移动数据与 Wi-Fi 共享关闭，开启隔离热点并确认可见，再复测同一页面的下发。

手机再次显示 `WIFI_CONNECT_FAILED` 后，Mac 扫到 2.4 GHz 隔离热点，蓝牙回读样机已连接目标并获 IP。在已连接状态下，Mac 通过同一 BLE 配网命令重现旧固件先报 `WIFI,ERR,connect` 和 `12295`，再成功连接。小程序已改为等待目标热点和有效 IP，临时断开或驱动重连通知不提前结束，明确格式或配置错误仍失败。状态查询只接收相应状态帧。回归覆盖现场通知顺序、错网络、明确失败及超时。安卓修正版真机复测通过，实测结果见上表。

正式预览进入设备自检后，截图显示麦克风与振动片未通过。远端只读检查确认同一台样机已绑定，未上报运行快照，也无云端在线记录。自检改为说明未收到状态，可选雷达不列入失败项；失败时可查看已绑定设备。未收到真实状态时仍保留自检未完成，回归验证不保存校准凭据或完成标记。

真机截图确认首页可打开。首页旧版把未回报的振动片当作未连接，并显示今晚仅记录；首页加载还可能早于 BLE 重连。已修正为按实际回报展示，并在蓝牙重连结束后读取依赖蓝牙的状态。测试覆盖重连成功、重连失败后继续读取云端状态，以及未知和明确断开的区别。新版首页待手机复核。

新版首页真机截图确认蓝牙已连接、振动片状态待确认。现装 `1.0.2` 的串口曾对安全状态与输出状态查询 `0x24`、`0x27` 报未知指令，首页读音效或夜灯状态可能随之超时。已修正首页在蓝牙连接但无安全回读且控制不可用时省去重复的输出查询，改为说明声音和夜灯暂不可用。回归验证既不会再次发出查询，也不会放开控制。

真机截图确认首页蓝牙已连接，提示设备安全状态及振动片状态待确认，声音和夜灯入口显示为不可用。 这次确认首页状态展示符合现装固件回报，未验证实际控制和振动片硬件反馈。

按硬件负责人要求复测当前连接的 ESP32。Mac 通过 BLE 读到固件 `1.0.2`，在等待窗口内未收到 `0x24` 安全状态或 `0x27` 输出状态回报。候选固件的 56 项 Node 测试及主机 C 检查已复跑通过。候选版实际播放、夜灯及全停仍需已装候选固件的测试板。

针对「下午能发声和亮灯」复测现装样机。Mac 通过旧版 BLE 协议在 25% 音量下播放已有短音效，设备回报开始和结束，随后确认停止写入并恢复启动音量。台架人员确认听到了声音，短按实体键时灯带切换。两项均为现场手动功能实测。正式小程序的输出安全回读与全停仍需候选固件真机验收。

振动片接好并由台架人员确认平放桌面后，Mac 向现装 `1.0.2` 写入一次 10% 的手动短振指令，约 0.7 秒后自动写入停止。启动和停止均得到 BLE 写入应答。实际振动是否出现和停止仍待台架人员回报，写入应答不作为物理通过。

台架人员回报 10% 短振未感觉到振动。随后按同一桌面布置补测一次 25%、约 0.7 秒，BLE 启动和停止写入均有应答，实物振感待回报。若仍无振感，继续检查驱动供电、共地和 GPIO42 到驱动输入的信号。

2026-11-08。上一轮 25% 测试后，台架人员报告线路松开，暂停振动测试。现场报告重新接好后，Mac 再对同一台现装 `1.0.2` 样机下发一次 25%、约 0.7 秒的短振。启动和停止均收到 BLE 写入应答，台架人员确认没有感觉到振动。

按台架人员要求再发一次相同的短振，并同步采集串口。BLE 启动和停止均收到写入应答，串口出现 `cmd: motor stop`，未捕获可用于确认启动的固件日志，GPIO42 电平和本次实物反馈待确认。
